# rental-contract-scan：租赁合同风险审查

> 目标：把"凭感觉看合同"变成"机器先扫一遍、人再按清单复核"的固定流程。
> 核心纪律：**先跑脚本（机器），再做五维复核（人）；有 blocker 不改，就不建议签字。**
>
> ⚠️ 非律师意见声明：本 skill 输出为通用风险提示，不是法律意见；各地租赁条例差异大，以当地最新规定为准。

## 1. 何时使用

- 拿到房东/中介给的租赁合同，准备签字前 → 跑全流程
- 续租、转租要签补充协议前 → 跑全流程（补充协议同样适用）
- 只想快速看一眼 → 只跑第 2 步脚本，10 秒出结果
- 已经签完想复盘 → 跑第 2+3 步，知道自己手里这份合同的弱点在哪

## 2. 第一步：跑确定性审计脚本（必做，零模型成本）

在你所在平台执行本地脚本的方式运行插件自带脚本：

```
python3 <插件目录>/scripts/audit/contract_audit.py --target <合同文本所在目录> --format text
```

合同文本可以是用户粘贴的 `.txt`/`.md` 文件。脚本做 17 条规则检查：

| 类别 | 规则示例 | 严重级 |
|---|---|---|
| 霸王条款 | 押金无条件不退、单方任意涨价、维修全转嫁、押金扣除任由对方解释、违约金只约束承租方 | blocker |
| 金额异常 | 押金 > 1 个月租金预警；押金 > 3 个月租金高危 | warning / blocker |
| 信息缺失 | 出租人身份、房屋权属、交接清单、租期起止缺失 | blocker |
| 信息缺失 | 月租金额、提前解约、维修划分、押金退还时限缺失 | warning |

- 有 blocker 时脚本以 exit code 2 退出——这是设计，不是 bug。
- 脚本只做"关键词级"判定：它能抓住"押金概不退还"这种明目张胆的，抓不住"解释权归甲方"藏在补充条款里的变体——那是第 3 步人工复核的事。

## 3. 第二步：五维人工复核清单

脚本跑完，按下面五个维度逐项打勾。每一项都要有依据（合同第几条原文），不能凭印象。

### 维度一：钱（押金 / 租金 / 违约金）

- [] 押金金额 ≤ 1 个月租金？（超了→谈判话术见第 5 节）
- [] 押金扣除标准是"清单+发票"还是"对方酌情"？后者必须改
- [] 押金退还写死天数了吗？（"验收合格后 X 日内原路退还"，X 建议 ≤ 15）
- [] 违约金双向对等吗？只罚承租方不罚出租方 → 补出租方违约责任
- [] 租金支付方式/到账日/逾期宽限写清了吗？

### 维度二：权（谁有权做什么）

- [] 出租人身份可验证吗？（身份证/营业执照 + 房产证名字对得上）
- [] 二房东/公司转租：有原房东的书面转租授权吗？授权期限覆盖你的租期吗？
- [] 转租/合租条款是"一刀切禁止"还是"经书面同意可转租"？后者对年轻人友好得多
- [] 出租方提前收房（如卖房）要赔你多少？没写=白纸

### 维度三：房（房子本身的状态与责任）

- [] 有《房屋设施交接清单》附件吗？品牌、型号、成色、照片四件套
- [] 维修责任划分：自然损耗谁修、人为损坏谁修、报修响应时限
- [] 甲醛/漏水等隐蔽问题：合同里有没有"交付时符合居住安全标准"的兜底句
- [] 物业费/暖气费/停车费谁承担？（最容易扯皮的三项）

### 维度四：退（退租与续租）

- [] 提前解约：通知期几天？违约金上限多少？（建议：30 天通知 + 不超 1 个月租金）
- [] 退租验收流程：当场验收还是"回头再算"？必须是当场
- [] 续租：涨幅上限写了吗？优先续租权写了吗？
- [] 合同到期自动续约的条款有吗？（有的话看清条件，别被"自动续一年"绑住）

### 维度五：坑（文字游戏）

- [] "解释权归甲方所有"→ 删掉，改为"争议协商解决，协商不成按第 X 条争议解决"
- [] 口头承诺（"家具都是新的""随时可退"）有没有写进合同或补充条款？没写=没说过
- [] 补充条款/附件有没有和正文矛盾的地方？（以"补充条款优先"字样+双方签字为准）
- [] 落款：双方签字+日期+身份证号，缺一不可；骑缝章（多页合同）

## 4. 第三步：输出《合同审查报告》

按以下结构输出，用户可直接拿去跟房东谈：

```
⛔ 别签 / ⚠️ 谈完再签 / ✅ 可签（三选一，一句话理由）
（每条：合同原文 → 为什么危险 → 改写建议原文）
（每条：风险点 → 谈判话术要点）
（带勾选框：要对方补充的材料清单）
```

结论三选一的纪律：有未整改的 blocker → 只能是"别签"或"谈完再签"，不许说"可签"。

## 5. 常见谈判话术（可直接用）

- **押金超 1 个月**："X 哥，我查了下现在正规合同押金都收 1 个月，咱们押一付三我能接受，押金就按 1 个月走，多出的我直接转成预付租金，你看行不？"
- **删霸王条款**："这条'押金概不退还'咱们改成'按交接清单实际损失扣除'吧，对你也有保障，真有损坏我跑不了。"
- **补退还时限**："押金退还咱们写个时间，验收合格后 7 天内原路退回，省得回头咱俩都惦记。"
- **要权属证明**："麻烦把房产证拍我一下，我就确认下房子是您的，身份证号我打码存档，签完就删。"

话术原则：给对方面子（"对你也有保障"）、给台阶（"正规合同都这样"）、留书面（谈完的修改必须落在纸面上）。

## 6. 各地差异速查指引（不编条文号，只给查法）

各地住房租赁条例差异大，本 skill 不背诵具体条文。需要确认时按这个顺序查：

1. 先看合同履行地城市的住建局/住房保障官网，搜"住房租赁条例"+"押金"。
2. 重点看三项：押金上限（多地倡导/规定不超过 1 个月租金）、租金贷/长收短付监管、中介备案要求。
3. 把查到的原文截图存档，谈判时引用"X 市住房租赁条例第 X 条"比"我觉得"管用 10 倍。
4. 查不到/看不懂 → 打 12345 问"租房押金纠纷归哪个部门管"，一次问清受理部门和所需材料。

**诚实说明**：本插件的脚本规则（如"押金超 1 个月预警"）用的是"多地通行做法"口径，不是全国统一法条。你的城市如果更严（或更松），以当地规定为准，脚本的 warning 级别供你谈判用，不算法定结论。

## 7. 补充协议模板要点（续租/转租/换室友时用）

- 标题写清"《房屋租赁合同》补充协议（一）"，编号防篡改。
- 首句锁定主合同："甲乙双方于 X 年 X 月 X 日签订的《房屋租赁合同》（以下简称原合同）…"
- 只写"变更事项"，不重复原合同：如"原合同第五条变更为：…"。
- 兜底句："本协议未涉及事项，仍按原合同执行；本协议与原合同不一致的，以本协议为准。"
- 双方签字+日期，与原合同相同的签署规范。

## 8. 反模式（这些做法是错的）

1. **"中介说这是标准合同，大家都这么签"** → 没有标准合同，只有对你有利和不利的合同。标准话术=不想改。
2. **只看租金不看押金条款** → 押金纠纷占租房纠纷的大头，租金谈下来 200，押金被扣 3000。
3. **口头承诺当真** → "你放心住"不写进合同=没说过。所有承诺落纸面。
4. **为清零 blocker 改脚本阈值** → 这是作弊。脚本是尺子，弯的是尺子不是合同。
5. **微信语音谈条件** → 语音难取证。所有关键沟通用文字，语音转文字后让对方确认。

## 9. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 脚本是否真的跑了（而不是"我觉得没问题"）？→ 没跑不算做。
2. 五维清单是否逐项打勾且有合同原文依据？→ 打勾要有出处。
3. 结论是否是三选一之一？→ 不许模棱两可。

标准冒烟用例：对插件自带的 `fixtures/` 跑脚本，确认坏 fixture 的 blocker 全命中、好 fixture 零 blocker（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-rental/issues，正文写清"输入 → 错误输出 → 期望输出"。规则误报/漏报请附最小复现文本。
